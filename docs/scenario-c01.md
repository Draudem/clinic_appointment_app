# Сценарий С-01 «Запись на приём» и переход в С-03 «Перенос»

Реализация регламента РГ-ТЕЛ-01 (сценарий С-01, ветвление «уже есть активная
запись» → С-03) в бэкенде `clinic_appointment_app`.

## Что делает голосовой ассистент

```
позвонивший → Asterisk → AudioSocket:8091 → распознавание речи
                                        ↓
                        BookingFlow (сценарий С-01)
                                        ↓
                        «Спасибо, записываю» → трубку кладёт
```

Полный цикл на живом звонке:

| Реплика пациента | Что делает ассистент |
|---|---|
| (звонок) | «Здравствуйте! Регистратура поликлиники номер семь, виртуальный помощник. Разговор записывается. Чем могу помочь?» |
| «Хочу записаться к стоматологу» | «Назовите, пожалуйста, фамилию, имя, отчество и дату рождения» |
| «Смирнова Ольга Викторовна, двенадцатое марта семьдесят восьмого» | «Спасибо, Ольга Викторовна. Ближайшее время: в четверг в девять; в пятницу в одиннадцать; в понедельник в девять. Что вам подходит?» |
| «Второй вариант» | «В пятницу, шестнадцатого октября, в одиннадцать. Записываю? Ответьте «да» или «нет».» |
| «Да» | «Готово, вы записаны. В пятницу, шестнадцатого октября, в одиннадцать, Смирнов Алексей Викторович. SMS придёт на этот номер.» → трубка кладётся |

## Переход в С-03

Если у пациента уже есть активная запись на эту специальность, сценарий С-01
не создаёт вторую, а предлагает перенос (ветвление «Уже есть активная запись»
регламента, раздел 5 С-01):

| Реплика | Действие |
|---|---|
| «Хочу записаться к стоматологу» | «У вас уже есть запись: Смирнов Алексей Викторович, в пятницу, шестнадцатого октября, в одиннадцать. Хотите перенести её?» |
| «Да» или названное время | предлагает новые слоты, затем подтверждение |
| «Да» на перенос | новая запись создаётся, **старая отменяется только после** — порядок из раздела 5 С-03 |

## Архитектура: каждый этап заменяем

```
AsteriskAudioSocketServer ──▶ CallDialogueService ──▶ BookingFlow (FSM)
                                                           │
 ┌──────────────┬──────────────────┬──────────────┬──────────────┬──────────────┐
     ▼              ▼                  ▼              ▼              ▼
CommandParser  TimeResolver    PatientIdentityResolver  SlotResolver  AppointmentService
NLU | rule    текст + модель    БД | заглушка   ScheduleProvider     БД
              RussianTime                    db | excel
```

| Этап | Порт | Что можно заменить |
|---|---|---|
| Разбор реплики | `CommandParser` | модель коллеги, словарь, LLM (Ollama) |
| Время и даты | `TimeResolver` + `RussianTime` | отдельный сервис календаря |
| Идентификация | `PatientIdentityResolver` | МИС, ЕПГУ, заглушка |
| Расписание | `ScheduleProvider` | БД, Excel, МИС |
| Запись | `AppointmentService` | МИС клиники |

Ни один из этих этапов не знает о существовании остальных, поэтому любой
заменяется заглушкой или более сильной моделью без правок соседей.

## Расписание: БД или Excel

Переключается одной переменной окружения:

```bash
SCHEDULE_SOURCE=db      # по умолчанию: таблица doctors
SCHEDULE_SOURCE=excel   # файл data/schedule.xlsx
SCHEDULE_EXCEL_PATH=путь/к/файлу.xlsx
```

Формат файла — первая строка заголовки, дальше по одному приёму в строке:

| ФИО | Специальность | Дата | Время | Кабинет |
|---|---|---|---|---|
| Смирнов Алексей Викторович | Стоматолог | 2026-11-02 | 09:00 | 201 |

- Заголовки распознаются по первым буквам: `ФИО`/`Врач`, `Дата`/`День`, `Кабинет`.
- Дата принимается и текстом (`2026-11-02`, `02.11.2026`), и как настоящая дата Excel.
- Время — и текстом (`09:00`, `9.00`), и настоящим временем Excel.
- Файл перечитывается при изменении, подкладывать новое расписание можно без перезапуска.
- Врачи сопоставляются со справочником `doctors` по ФИО. Незнакомое ФИО пропускается:
  записать пациента «в никуда» нельзя.

Тестовый файл создаётся командой:

```bash
./gradlew genSchedule     # -> data/schedule.xlsx
```

## Идентификация пациента

Регламент 3.5 требует ФИО и дату рождения перед любой записью, и запрещает
ассистенту называть эти данные первым — это защита от звонящего с чужого телефона.

- `PatientNameParser` разбирает сказанное без нейросети: фамилия, имя, отчество
  и дата рождения словами или цифрами («двенадцатое марта семьдесят восьмого»,
  «05.05.1962», «двенадцатое три семьдесят восемь»).
- `PatientIdentityResolver` ищет пациента. Найдено несколько — личность **не**
  устанавливается, идёт перевод по R-07: выбирать наугад нельзя.
- Демонстрационные пациенты создаются при старте (`smirnova/smirnova`,
  `petrov/petrov`, `ivanov/ivanov`). Отключается настройкой `app.seed-patients=false`.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SCHEDULE_SOURCE` | `db` | источник расписания: `db` или `excel` |
| `SCHEDULE_EXCEL_PATH` | `data/schedule.xlsx` | файл расписания |
| `VOICE_PARSER` | `nlu` | разбор реплик: `nlu`, `rule`, `rag-llm` |
| `VOICE_MAX_EXCHANGES` | `5` | лимит обменов до перевода оператору |
| `TTS_ENABLED` | `true` | озвучка ответов в трубку |
| `STT_ENABLED` | `true` | распознавание речи, порт AudioSocket 8091 |

```bash
./gradlew test        # 59 тестов
./gradlew genSchedule # тестовое расписание Excel
```

Покрыто: полный цикл записи и отказ от неё, идентификация, переход в С-03 и сам
перенос, красные флаги А и Б, просьба оператора, «вы робот», лестница непонимания,
